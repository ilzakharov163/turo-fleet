# Fleet Manager — Turo (контекст проекта для Claude)

Веб-приложение для управления автопарком на Turo: машины, простои, расходы, клеймы, наклейки, доходы, отчёты в Telegram.
Владелец — Илья (admin). Общение — на русском, коротко и по делу. Владелец не программист: объяснять простыми словами, показывать результат, не ломать данные.

## Стек и инфраструктура
- Next.js 16 (App Router, React 19), TypeScript, Tailwind v4, date-fns v4 (`ru` locale), lucide-react.
- Код приложения: папка `turo-fleet-archive/` репозитория `ilzakharov163/turo-fleet`. Ветка `main`.
- Деплой: Vercel, автодеплой из `main`. Прод: https://turo-fleet-archive.vercel.app
- База: Supabase, project id `fsvttaesxlwhndcwtqqz`. Клиент: `createClient()` из `@/lib/supabase`. Лог действий: `log(action, entity, id, details)` из `@/lib/logger` (таблица `activity_log`).
- Стиль UI: карточки `bg-white rounded-[18px] border border-gray-100/80 card-shadow`, акцент indigo (#4F46E5), таблицы с сеткой `border-gray-200`, шапки `bg-gray-100`, цифры `tabular-nums`. Мобильная версия обязательна (нижняя навигация, горизонтальный скролл таблиц внутри `overflow-x-auto`).
- В `src/app/(app)/layout.tsx` у колонки контента стоит `min-w-0` — не убирать (иначе на телефоне страница уезжает вбок).

## Разделы (src/app/(app)/…)
Порядок в меню: Дашборд, Авто, Календарь, Расходы, Доходы, Клеймы, Наклейки, Аналитика, Команда, История, Отчёты. (Тех.обслуживание убрано из меню.)
- **dashboard** — кликабельные карточки (Прибыль, Автомобили, Активных, Расходы за месяц, Зарплата работника), быстрые действия, «Требует внимания», «Сейчас в простое».
- **cars** — машины (`cars`: make, model, plate, delisted, owner_group).
- **calendar** — простои (`car_blocks`: car_id, start_date, end_date null = бессрочно, reason) + калькулятор зарплаты работника.
- **expenses** — расходы по машинам (`expenses`: car_id, title, amount, date, files, paid, notes), фильтр по категориям.
- **income** — «Доходы» (см. ниже, самый большой раздел).
- **claims** — клеймы (`claims`: status waiting/in_repair/done, opened_date, completed_date, initial_payment_received, supplement_paid, notes). Завершённые показывают только машину, номер и дату завершения.
- **stickers** — наклейки (`sticker_cars`, `sticker_changes` с old_plate/new_plate). Замена каждые 45 дней, жёлтый за 7 дней. При замене вводится новый номер → обновляется `cars.plate` везде.
- **team** — пользователи через RPC `list_team()`, `update_team_member(p_id, p_role, p_permissions, p_full_name)`. Роли admin/partner/employee, `profiles.permissions text[]` — список разделов. Новый пользователь = employee с доступом только к `/expenses`. Ограничение доступа — только на уровне UI (Sidebar), RLS даёт полный доступ авторизованным.
- **reports** — готовые сообщения для Telegram (navigator.share → иначе копирование) + Excel (CSV с BOM): Автопарк сегодня, Клеймы (формат «Initial получен: да/нет», «Supplement получен: да/нет»), Зарплата работника, Доходы (с платежами). Есть «Все отчёты одним сообщением».

## Правило зарплаты работника (везде одинаково)
За месяц по каждой машине в листинге: простой < 14 дней → $150; ≥ 14 дней → $75; простой весь месяц → $0. Расчёт в последний день месяца.

## Раздел «Доходы» (income/page.tsx)
Перенесён 22.10.2026 из старого TuroTracker (nzturotracker.netlify.app, больше не используется). Сверено построчно — совпадает до цента.

**Таблицы Supabase:**
- `revenue_accounts` (key, label, sort, active_from, active_until): M Миша (1), I Адилет (2), R Радвизон (3), A Анастасия (4), V Вова (5, активен до 2026-09), O Олег (скрыт: active_until 2026-05-01). Порядок везде: Миша → Адилет → Радвизон → Анастасия.
- `revenue_cars` (account, name, car_id → cars, added_from, sold_from, sort). Chevrolet и Acura 111 проданы с 2026-10.
- `revenue_entries` (revenue_car_id, period = 1-е число месяца, gross, repair, claim_items jsonb [{claim, supplement, pct}], other_items jsonb [{desc, amount}]), unique(revenue_car_id, period).
- `revenue_month_expenses` (period, salary1 = «Затраты на сотрудника: Расходы», salary2 = «Зарплата», items jsonb [{desc, amount}]).
- `revenue_payments` (period, grp «Наши»/«Миша»/«Карам»/…, day, name, amount, sort; колонка paid не используется в UI). Список автоматически копируется в текущий месяц из последнего месяца при первом открытии страницы.
- `tracker_archive` (key, value jsonb) — полная сырая копия 299 записей старого трекера, только чтение.

**Формулы:**
- вычет = Σ supplement × pct
- итог машины = gross + Σ claim + Σ supplement − вычет − ремонт − Σ прочее
- чистая прибыль месяца = Σ итогов аккаунтов − (salary1 + salary2 + Σ расходов компании) − Σ платежей

**UI:** лента месяцев с прибылью; вкладки Сводка / Ввод Gross / аккаунты / Расходы / Платежи.
- Сводка: компактная строка (прибыль, Gross, Клеймы чистыми, Прочее, Расходы, Платежи, Telegram) + таблица «По аккаунтам» (Клеймы = после вычета и ремонта, отдельно Прочее, Итог, Доля) + строки Расходы компании, Платежи, Чистая прибыль + график по месяцам + лучшие/в минусе.
- Вкладка аккаунта — таблица как Excel: белые ячейки редактируются (NumCell: Enter — вниз, Tab — вправо, автосохранение), серые считаются. Клик по названию машины → боковая панель (несколько клеймов, прочие расходы, история, привязка к парку, «продана»).
- «Ввод Gross» — все машины всех аккаунтов одним списком для ввода в конце месяца (с подсказкой «было» за прошлый месяц).
- «Выгрузить»: этот месяц / все месяцы (CSV) / резервная копия JSON (включая tracker_archive и платежи).

**Исторические заметки:** в августе добавлен Supplement $6,538 (20%) по Bmw X1 у Анастасии (в трекере был скрыт). Записи X1 на аккаунте Ильи не переносить. В августе/сентябре платежи записаны строкой «пейменты» в расходах — отдельные платежи начинаются с октября 2026.

**Карточка «Прибыль» на Дашборде:** чистая прибыль последнего месяца, где уже внесён Gross (текущий месяц заполняется в конце, без Gross он бы показал ложный минус), и разница с предыдущим месяцем. Формулы те же, что в «Доходах». Видна только admin или тем, у кого в permissions есть `/income`. Клик → /income.

## Как работать с проектом
- Перед изменением схемы — посмотреть текущие таблицы; RLS-политика по образцу: `"auth users full access" for all to authenticated using (true) with check (true)`.
- Не менять и не удалять данные без явного согласия владельца. Не вводить пароли.
- После изменений: `npm run build` (или проверить статус деплоя Vercel), проверить страницу на сайте, в том числе на ширине телефона.
