# Fleet Manager — Turo (контекст проекта для Claude)

Веб-приложение для управления автопарком на Turo: машины, простои, расходы, клеймы, наклейки, доходы, отчёты в Telegram.
Владелец — Илья (admin). Общение — на русском, коротко и по делу. Владелец не программист: объяснять простыми словами, показывать результат, не ломать данные.

## Стек и инфраструктура
- Next.js 16 (App Router, React 19), TypeScript, Tailwind v4, date-fns v4 (`ru` locale), lucide-react.
- Код приложения: папка `turo-fleet-archive/` репозитория `ilzakharov163/turo-fleet`. Ветка `main`.
- Деплой: Vercel, автодеплой из `main`. Прод: https://turo-fleet-archive.vercel.app
- База: Supabase, project id `fsvttaesxlwhndcwtqqz`. Клиент: `createClient()` из `@/lib/supabase`. Лог действий: `log(action, entity, id, details)` из `@/lib/logger` (таблица `activity_log`).
- Тема: всегда как в системе (iPhone/Mac). Класс `dark` на `<html>` ставит скрипт в `app/layout.tsx` до отрисовки, `ThemeContext` следит за переключением. Тёмная палитра — подмена CSS-переменных Tailwind в `globals.css` (`html.dark { --color-white, --color-gray-*, --color-*-50/100 … }`), поэтому новые классы работают сами. Не использовать светлые hex-цвета в классах (`bg-[#EEF2FF]` и т.п.) — брать `bg-indigo-50` и т.д. Значки — мягкие подложки (`bg-indigo-50 text-[#4F46E5] dark:text-indigo-300`), без градиентов.
- Стиль UI: карточки `bg-white rounded-[18px] border border-gray-100/80 card-shadow`, акцент indigo (#4F46E5), таблицы с сеткой `border-gray-200`, шапки `bg-gray-100`, цифры `tabular-nums`. Мобильная версия обязательна (нижняя навигация, горизонтальный скролл таблиц внутри `overflow-x-auto`).
- В `src/app/(app)/layout.tsx` у колонки контента стоит `min-w-0` — не убирать (иначе на телефоне страница уезжает вбок).
- Телефон (< 640px, `sm:`): у `main` стоит `overflow-x-clip`, у html/body `overscroll-behavior: none` — страница не двигается вбок. Широкие таблицы на телефоне не показываем: Авто, Расходы, Календарь имеют отдельный мобильный вид карточками (`sm:hidden`) и таблицу/сетку для компьютера (`hidden sm:block`). Плавающие кнопки поднимать над нижним меню: `bottom-[calc(5.5rem+env(safe-area-inset-bottom))] sm:bottom-6`.
- Боковое меню (Sidebar.tsx): `sm` — 72px только значки, `lg` — 232px со значками и подписями; отступ контента `sm:ml-[72px] lg:ml-[232px]`, контент до 1400px. Шапка (TopBar): название раздела + дата, имя и роль.
- Нижнее меню телефона (Sidebar.tsx): 4 главных раздела `MOBILE_MAIN` (Дашборд, Авто, Расходы, Доходы) + «Ещё» — панель снизу с Отчётами, Настройками и «Выйти».

## Разделы (src/app/(app)/…)
С 22.10.2026 шесть разделов: Дашборд, Авто, Расходы, Доходы, Отчёты, Настройки. Разделы с вкладками собраны через `components/SectionPage.tsx` (`?tab=key`); содержимое вкладок — в `components/views/*View.tsx`. Старые адреса `/calendar`, `/claims`, `/stickers`, `/analytics`, `/team`, `/log` перенаправляют на нужную вкладку.
- Доступ: `useAccess()`/`canAny()` из `src/lib/access.ts` (те же правила, что `can_any` в базе). У каждого пункта меню (Sidebar `nav[].access`) и каждой вкладки (`SectionTab.access`) — список галочек, хотя бы одна из которых нужна; `[]` — всем, `ADMIN_ONLY` — только админ. Ключи галочек остались прежними (`/cars`, `/claims`, `/stickers`, `/reports`, `/analytics`, `/log` …), поэтому правила базы не менялись.
- **Авто** (`/cars`): Машины (`/cars`) · Простои и зарплата (`/cars`, старый `/calendar`) · Клеймы (`/claims`) · Наклейки (`/stickers`).
- **Отчёты** (`/reports`): Отчёты (`/reports`) · Прибыль машин (`/income`, `components/views/CarProfitView.tsx`) · Аналитика (`/analytics`). «Прибыль машин» — итог каждой машины (как в «Доходах», до расходов компании/зарплаты/платежей) «За месяц» или «За всё время» (количество месяцев с данными, период, в среднем за месяц); сгруппировано **по аккаунтам** (порядок аккаунтов по sort; внутри — по итогу; подытог аккаунта) — так же в тексте Telegram («👤 Аккаунт — сумма (машин: N)» + список) и в Excel (секция на аккаунт с итогом); машина, работавшая в двух аккаунтах, — в каждом со своей частью; «уже нет» — продана/убрана/аккаунт закрыт. Telegram, копирование, Excel. Сверено с базой: октябрь = «Итого по аккаунтам».
- **Настройки** (`/settings`): Профиль (всем) · Команда (только админ) · История (`/log`).
- **dashboard** — кликабельные карточки (Прибыль, В работе, Расходы, Зарплата, Клеймы), быстрые действия, «Требует внимания», «Сейчас в простое».
- **cars** — «Авто», вкладки Машины и Простои: «Машины» (`components/views/CarsView.tsx`, таблица `cars`: make, model, plate, delisted, owner_group) и «Простои и зарплата» (`/cars?tab=downtime`, `components/views/DowntimeView.tsx`: `car_blocks` — car_id, start_date, end_date null = бессрочно, reason — и расчёт зарплаты работника). `/calendar` перенаправляет на вторую вкладку. Старая галочка `/calendar` в permissions даёт доступ к «Авто» (Sidebar); в «Команде» её больше нет. Блок «История выплат» удалён (таблицы `salary_payments` в базе нет).
- **expenses** — расходы по машинам (`expenses`: car_id, title, amount, date, files, paid, notes), фильтр по категориям.
- **income** — «Доходы» (см. ниже, самый большой раздел).
- **claims** (Авто → Клеймы, `ClaimsView`) — клеймы (`claims`: claim_number (номер Turo, уникальный без учёта регистра, обязателен для новых), description (коротко «что случилось»), status waiting/in_repair/done, opened_date, completed_date, initial_payment_received, supplement_paid, still_listed, notes). Поиск по номеру/машине/описанию (по всем месяцам). Завершённые показывают машину, номер клейма и дату завершения. Номер и описание — и в отчёте «Клеймы».
- **Клеймы → Доходы (с 25.10.2026, `lib/claimIncome.ts`):** нажатие Initial / Supplement в Клеймах открывает окно «Сумма, $» + месяц «Доходов» (по умолчанию текущий), у Supplement ещё «Вычет Turo, %» (по умолчанию 20, владелец меняет сам). Сохранение пишет сумму в `claim_items` записи «Доходов» машины за этот месяц: один клейм = одна строка с `claim_id` (Initial → claim, Supplement → supplement + pct); повторный ввод заменяет сумму, смена месяца переносит её. В клейме хранятся `initial_amount/initial_period`, `supplement_amount/supplement_pct/supplement_period` (миграция `claims_payments`), сумма видна на кнопке. «Снять» в окне обнуляет сумму в «Доходах» (строка без сумм удаляется). Без доступа к `/income` сумма сохраняется только в клейме. В панели машины «Доходов» такая строка помечена «из Клеймов», `claim_id` сохраняется при правке. Строки, внесённые в «Доходы» руками до 25.10, с клеймами не связаны — повторный ввод через Клеймы добавит вторую строку.
- **В простой / снять с листинга** (Авто → Машины, `components/UnlistSheet.tsx`; открывается и кнопкой статуса «В работе» — ей владелец пользуется чаще, и кнопкой «Снять с листинга»; даты «с» и необязательная «по»): причина «Клейм» (номер*, описание, дата) → создаётся клейм «Ожидает ремонта», still_listed=false, и простой с этой даты с причиной «Клейм № … — описание»; «Другая причина» → только простой с причиной. Флаг `cars.delisted` больше не ставится (машина в простое — зарплата по правилам простоя); «Вернуть в листинг» остаётся только для старых снятых машин. Вернуть в работу — кнопкой статуса «В простое».
- **stickers** (Авто → Наклейки, `StickersView`) — наклейки (`sticker_cars`, `sticker_changes` с old_plate/new_plate). Замена каждые 45 дней, жёлтый за 7 дней. При замене вводится новый номер → обновляется `cars.plate` везде.
- **team** (Настройки → Команда, `TeamView`) — пользователи через RPC `list_team()`, `update_team_member(p_id, p_role, p_permissions, p_full_name)`. Роли admin/partner/employee, `profiles.permissions text[]` — список разделов. Новый пользователь = employee с доступом только к `/expenses`. Пользователей создаёт админ в кабинете Supabase (старые /api/invite и /join удалены 22.10.2026 — были открыты без проверки). Галочки ограничивают и меню (Sidebar), и саму базу (RLS по разделам, см. «Безопасность и доступ»). Публичная регистрация в Supabase должна быть выключена.
- **reports** (`ReportsView`) — готовые сообщения для Telegram (navigator.share → иначе копирование) + Excel (CSV с BOM): Автопарк сегодня, Клеймы (формат «Initial получен: да/нет», «Supplement получен: да/нет»), Зарплата работника, Доходы (с платежами). Есть «Все отчёты одним сообщением».

## Правило зарплаты работника (везде одинаково)
За месяц по каждой машине в листинге: простой < 14 дней → $150; ≥ 14 дней → $75; простой весь месяц → $0. Расчёт в последний день месяца.
**Штрафы и вычеты** (с 23.10.2026): таблица `salary_deductions` (date, reason, amount). Записываются по ходу месяца — основное место «Доходы → Расходы → Затраты на сотрудника», то же самое в «Авто → Простои и зарплата» (общий компонент `components/DeductionsEditor.tsx`). К выплате работнику = итог по машинам − вычеты месяца (Простои, Отчёты, Дашборд «Зарплата»).

## Раздел «Доходы» (income/page.tsx)
Перенесён 22.10.2026 из старого TuroTracker (nzturotracker.netlify.app, больше не используется). Сверено построчно — совпадает до цента.

**Таблицы Supabase:**
- `revenue_accounts` (key, label, sort, active_from, active_until): M Миша (1), I Адилет (2), R Радвизон (3), A Анастасия (4), V Вова (5, активен до 2026-09), O Олег (скрыт: active_until 2026-05-01). Порядок везде: Миша → Адилет → Радвизон → Анастасия.
- `revenue_cars` (account, name, car_id → cars, added_from, sold_from, sort). Chevrolet и Acura 111 проданы с 2026-10.
- `revenue_entries` (revenue_car_id, period = 1-е число месяца, gross, repair, claim_items jsonb [{claim, supplement, pct}], other_items jsonb [{desc, amount}]), unique(revenue_car_id, period).
- `revenue_month_expenses` (period, salary1 = «Затраты на сотрудника: Расходы», salary2 = «Зарплата», items jsonb [{desc, amount}]).
- `revenue_payments` (period, grp «Наши»/«Миша»/«Карам»/…, day, name, amount, sort; колонка paid не используется в UI). Список автоматически копируется в текущий месяц из последнего месяца при первом открытии страницы.
- `tracker_archive` (key, value jsonb) — полная сырая копия 299 записей старого трекера, только чтение.

**Формулы:**
- вычет = Σ supplement × pct
- итог машины = gross + Σ claim + Σ supplement − вычет − ремонт − Σ прочее − **платёж**
- **Платёж за машину** (с 23.10.2026): `revenue_entries.payment` (миграция `revenue_entries_payment`) — ежемесячный платёж (кредит/лизинг), только по машинам, где платим мы. `null` — не задан, `0` — платежа нет. Вводится в колонке «Платёж» таблицы аккаунта или в панели машины. При загрузке «Доходов» платёж сам переносится в **текущий** месяц из прошлого, если в текущем ещё `null` (для машин, видимых в текущем месяце в работающем аккаунте). Входит в итог машины, а значит в «Итого по аккаунтам», прибыль, Дашборд, Отчёты и «Прибыль машин» (колонка «Платежи»). Общие платежи (`revenue_payments`, вкладка «Платежи») остаются для того, что не относится к конкретной машине — владелец сам переносит оттуда платежи по машинам (Миша, Карам=Анастасия X1, BMW 3 → Токтоболот), иначе будет двойной учёт.
- три статьи расходов: **расходы компании** = Σ items; **затраты на сотрудника** = salary1 (расходы) + salary2 (зарплата) − вычеты, где вычеты отнимаются **только от внесённой зарплаты** (`staffCost` / `appliedDeductions` в `lib/calc.ts`): пока salary2 = 0 (зарплату вносят в последний день месяца) — вычеты не учитываются и показываются как «после ввода зарплаты»; больше зарплаты вычесть нельзя; **платежи** = Σ revenue_payments
- чистая прибыль месяца = Σ итогов аккаунтов − расходы компании − затраты на сотрудника − платежи (`monthProfit` в `lib/calc.ts`, параметр deductions). Так считают «Доходы» (Сводка, выгрузки, текст), Дашборд и Отчёты. Подсказка «положено по простоям» в «Зарплата» — до вычетов (вычеты вычитаются отдельной строкой).

**UI:** сверху `MonthPicker` (в сетке месяцев — прибыль каждого) и «Выгрузить»; вкладки одной полосой: Сводка · Gross · Аккаунты ▾ (выпадающее меню с аккаунтами и «Новый аккаунт») · Расходы · Платежи. Машины в аккаунтах и в Gross — по алфавиту (марка/модель, затем номер).
- Сводка: компактная строка (прибыль, Gross, Клеймы чистыми, Прочее, Расходы, Платежи, Telegram) + таблица «По аккаунтам» (Клеймы = после вычета и ремонта, отдельно Прочее, Итог, Доля) + строки Расходы компании, Платежи, Чистая прибыль + график по месяцам + лучшие/в минусе.
- Вкладка аккаунта — таблица как Excel: белые ячейки редактируются (NumCell: Enter — вниз, Tab — вправо, автосохранение), серые считаются. Клик по названию машины → боковая панель (несколько клеймов, прочие расходы, история, привязка к парку, «продана»).
- «Ввод Gross» — все машины всех аккаунтов одним списком для ввода в конце месяца (с подсказкой «было» за прошлый месяц).
- «Выгрузить»: этот месяц / все месяцы (CSV) / резервная копия JSON (включая tracker_archive и платежи).

**Название машины в «Доходах»** — всегда из «Авто»: при загрузке у привязанных `revenue_cars` поле `name` подменяется на `марка модель` (номер показывается отдельно). Новая машина добавляется только выбором из «Авто» (без ручного названия; в `name` пишется «марка модель номер» на всякий случай). Своё `name` остаётся только у непривязанных — это старые машины Вовы (аккаунт закрыт) и проданные Acura 111 / Chevrolet.

**Аккаунты и машины (с 23.10.2026):** кнопка «+ Аккаунт» во вкладках «Доходов» создаёт `revenue_accounts` (key — первая буква имени, при совпадении с номером; sort — в конец; active_from — выбранный месяц). «Аккаунт» в шапке вкладки аккаунта — переименовать и задать последний месяц (`active_until`). Убрать машину (продана/разбита): кнопка «Продана или разбита — убрать с <следующего месяца>» в панели машины «Доходов» и в карточке машины «Авто». Через `lib/fleet.ts` (`removeCarFrom` / `restoreCar`) ставит сразу `cars.removed_from` (миграция `cars_removed_from`) и `revenue_cars.sold_from` у всех записей, привязанных к машине. В текущем месяце машина считается как обычно. «В парке в месяце» — `inFleet(car, period)` из `lib/calc.ts` (не delisted и removed_from > period); используется в зарплате, Дашборде, Простоях, Отчётах, выборе машины в Клеймах/Наклейках. В «Авто → Машины» убранные — внизу «Проданы или разбиты» с «Вернуть»; до ухода — бейдж «Уходит с …». Месяцы «с …» писать в родительном падеже: `format(d, 'MMMM')` → «ноября» (`LLLL` → «ноябрь»).

**Исторические заметки:** в августе добавлен Supplement $6,538 (20%) по Bmw X1 у Анастасии (в трекере был скрыт). Записи X1 на аккаунте Ильи не переносить. В августе/сентябре платежи записаны строкой «пейменты» в расходах — отдельные платежи начинаются с октября 2026.

**Карточка «Прибыль» на Дашборде:** чистая прибыль текущего месяца (по желанию владельца; пока Gross не внесён — подпись «Gross за месяц ещё не внесён», иначе разница с прошлым месяцем). Формулы те же, что в «Доходах». Видна только admin или тем, у кого в permissions есть `/income`. Клик → /income.


## Безопасность и доступ (с 22.10.2026)
- RLS по разделам применён (миграция `rls_by_sections`, SQL в `supabase-rls-sections.sql`). `can_any(text[])` — true для admin или если в `profiles.permissions` есть хоть один из разделов (не-админ без разделов = `{/expenses}`); `is_member()` — у пользователя есть профиль.
- Карта: cars — читают все, insert/delete `/cars`, update `/cars,/stickers`; car_blocks — читают `/calendar,/cars,/dashboard,/income,/reports`, пишут `/calendar,/cars`; expenses — читают `/expenses,/dashboard,/analytics`, пишут `/expenses`; claims — читают `/claims,/dashboard,/reports`, пишут `/claims`; sticker_* — читают `/stickers,/dashboard`, пишут `/stickers`; revenue_*, tracker_archive — только `/income`; activity_log — каждый пишет свои записи, читает `/log`; maintenance — только admin; team_members — своя строка или admin; чеки (storage receipts) — `/expenses`.
- Новая таблица = сразу политики через `can_any(...)`, не «full access». Если раздел читает данные другого раздела — добавить его в список читающих, иначе он молча получит пустоту (пример: отчёт «Доходы» скрыт без `/income`).
- Старые API приглашений (`/api/invite`, `/api/join/*`, `/api/team/names`) и страница `/join` удалены — работали с сервисным ключом без проверки входа.

## Общие механизмы (с 23.10.2026)
- **Сообщения и подтверждения:** `notify(text, tone)` и `await ask(text, { detail, ok, danger })` из `src/lib/ui.ts`, показывает `components/ui/Feedback.tsx` (в `app/(app)/layout.tsx`). Системные `alert/confirm` не использовать.
- **Ошибки записи:** `createClient()` (`lib/supabase.ts`) оборачивает fetch: любая неудачная запись в базу/хранилище сама показывает красное сообщение («Нет связи…», «Нет прав…»). Не дублировать `alert(error.message)`, только `if (error) return`.
- **Формулы:** `src/lib/calc.ts` — `calcSalary`, `idleDaysInMonth`, `calcEntry` (итог машины), `monthExpensesTotal`, `monthProfit`. Тесты `src/lib/calc.test.ts`, запуск `npm test` (Node встроенный test runner). GitHub Actions `.github/workflows/ci.yml` (в корне репозитория) на каждый push в main: `npm ci`, `npm test`, `npm run build`. Статус — вкладка Actions на GitHub.
- **Статус машины** — только по простоям (`car_blocks`): в простое, если сегодня внутри простоя. Колонки `cars.status/inactive_reason` больше не показываются (status ещё пишется для совместимости). «Вернуть в работу» закрывает текущий простой вчерашним днём (начавшийся сегодня — удаляется).
- **Карточка машины** `components/CarCard.tsx` (клик по названию в «Авто → Машины»): простои, зарплата, расходы, клеймы, наклейка, доход (через `revenue_cars.car_id`). Блоки без доступа скрыты.
- **Резервные копии:** `supabase-backups.sql` (миграция `backups_daily`): pg_cron каждый день 10:00 UTC → `make_backup('auto')` пишет снимок всех таблиц в `public.backups` (30 авто + 10 ручных). Настройки → «Резервные копии» (только админ): список, скачать JSON, сделать сейчас. Фото чеков не входят.
- **Расходы — итоги (с 25.10.2026):** карточки «Расходы · N», «Оплачено», «Не оплачено» и «Переведено сотруднику» = поле «Расходы» в «Доходы → Расходы → Затраты на сотрудника» (`revenue_month_expenses.salary1`) за выбранный месяц (или 12 месяцев) + «остаток» = переведено − все расходы месяца (без учёта фильтров). Карточка — ссылка на `/income?view=expenses&month=yyyy-MM` («Доходы» читают `view`/`month` из адреса). Без доступа к «Доходам» карточки нет.
- **Старые номера (с 30.10.2026, `components/PlateHistory.tsx`, `lib/plates.ts`):** кнопка «Старые номера» (Авто → Машины под поиском; Клеймы рядом с «Добавить клейм»; в форме клейма «Не помню номер» — нажатие на машину выбирает её). Источник — `sticker_changes.old_plate/new_plate` («Наклейки → Замена номеров»; записи до 27.10.2026 без номеров). Поиск в Клеймах ищет и по старым номерам, в списке машин формы — «(был …)». `normPlate` сравнивает без пробелов/дефисов и переводит русские буквы-двойники в латиницу (номер 527АКР1 был набран по-русски, исправлен 30.10 на 527AKP1). При вводе номера («Авто» — добавить/изменить, «Наклейки → Замена номеров») `latinPlate` сразу меняет русские двойники на латиницу; остальные русские буквы (`hasCyrillic`) — ошибка «Номер латиницей».
- **Клеймы — новый клейм без листинга (с 30.10.2026):** «Добавить клейм» со снятой галочкой «Машина остаётся в листинге» (есть машина, статус не «Завершён») сразу вызывает `unlistByClaim` с датой «Открыт»: простой «Клейм № … — описание» с этой даты. Раньше простой не создавался (Altima 954AND1, клейм 1109872 — простой с 29.10 поставлен вручную 30.10).
- **Клеймы — снять с листинга позже (с 26.10.2026, `lib/unlist.ts` → `unlistByClaim`):** машина может кататься с открытым клеймом (still_listed=true) до Initial, потом уходит на supplement/ремонт. В карточке клейма (карандаш; или клик по «листинг активен») — блок «Машина ещё в листинге» с датой и кнопкой «Снять с листинга»: простой с даты «Клейм № … — описание» (если на эту дату простоя нет) и still_listed=false. В «Авто → В простой» номер уже открытого клейма ЭТОЙ машины не ошибка — машина снимается по нему (новый клейм не создаётся); номер чужой машины или завершённого клейма — ошибка.
- **Клеймы — «Завершить» (с 25.10.2026):** открывает окно: дата завершения (по умолчанию сегодня) и галочка «Вернуть машину в работу» (если на эту дату у машины есть простой; сначала ищется простой с номером клейма в причине). Сохранение: клейм done + completed_date (+ still_listed=true), простой заканчивается накануне даты (начался в тот же день — удаляется), `cars.status='active'`. В завершённых видно «открыт → завершён».
- **Клеймы — аккаунт машины (с 25.10.2026):** рядом с номером машины бейдж с точкой цвета и именем аккаунта «Доходов» (запись `revenue_cars`, числящаяся в текущем месяце, иначе последняя). Цвета аккаунтов общие — `lib/accountColors.ts`.
- **Авто → Машины:** карточки сверху «Всего / В работе / В простое» — фильтр списка (повторное нажатие или «Всего» — все).
- **Телефон:** масштабирование выключено (`viewport`: maximumScale 1, userScalable false), поля ввода 16px (иначе iOS приближает). «Доходы» на телефоне: аккаунт — карточки машин с полем Gross и кнопкой «Ещё» (панель машины), «По аккаунтам» — список; вкладки в одну строку.
- **Расходы:** фильтры одной строкой — `MonthPicker` (‹ Октябрь 2026 › + сетка месяцев, пункт «За 12 месяцев»), «Статьи» (выезжающее меню с галочками, несколько сразу), «Машины», «Без чека», поиск; итоги строкой над списком. Выезжающие панели — `components/ui/Popover.tsx` (компьютер — под кнопкой, телефон — снизу). Грузятся последние 12 месяцев; ссылки на чеки — по запросу; кнопки «Сфотографировать» (`capture="environment"`) и «Из галереи / файл»; новый расход подставляет машину и статью из последнего; поиск и фильтр «Без чека».
- **Визуал:** кнопки `btn-primary` / `btn-secondary` / `btn-danger` (globals.css), загрузка — `.skeleton`, окна на телефоне — панель снизу (`Modal` в PageShell), поля `inputCls` — 16px на телефоне (iOS не зумит). Заставки iPhone — `public/splash/*`, подключены в `appleWebApp.startupImage`.

## Как работать с проектом
- Перед изменением схемы — посмотреть текущие таблицы; политики RLS — по разделам через `can_any(...)` (см. «Безопасность и доступ»).
- Не менять и не удалять данные без явного согласия владельца. Не вводить пароли.
- После изменений: `npm test` и `npm run build` (или проверить статус деплоя Vercel), проверить страницу на сайте, в том числе на ширине телефона.
