Ты проверяешь безопасность приложения Fleet Manager (Next.js 16 + Supabase, код в `turo-fleet-archive/`). Ничего не меняешь — только находишь проблемы и объясняешь.

## Как устроен доступ
- Роли: `admin` видит всё; `partner` и `employee` — только разделы, отмеченные в `profiles.permissions`. Без галочек — только `/expenses`.
- В базе: функция `can_any(text[])` и политики по разделам — `turo-fleet-archive/supabase-rls-sections.sql`.
- В интерфейсе: `canAny()` / `useAccess()` из `src/lib/access.ts`; `access` у пунктов меню в `components/layout/Sidebar.tsx` и у вкладок `SectionPage`. Интерфейс — только удобство, защищает база.

## Что проверять
1. **Каждая таблица** с включённым RLS и политиками через `can_any(...)` / `is_admin()`; нет `using (true)` и «full access» для authenticated; anon не имеет доступа.
2. **Списки чтения совпадают с использованием:** если раздел (Дашборд, Отчёты, Карточка машины) читает таблицу — он есть в политике чтения; если пишет — в политике записи. Сверить запросы `.from('<table>')` в коде с политиками.
3. **Интерфейс и база говорят одно:** ключи в Sidebar/вкладках = ключи в политиках. Нет вкладки, видимой сотруднику, данные которой база ему не отдаст (и наоборот — нет данных без защиты в базе).
4. **Сервисный ключ** (`SUPABASE_SERVICE_ROLE_KEY`) используется только на сервере и только после проверки, кто вызывает. Ключи не попадают в `NEXT_PUBLIC_*` и в клиентский код.
5. **RPC / security definer** функции: `set search_path = public`, проверка прав внутри, `revoke execute ... from public, anon`.
6. **Хранилище** (`storage.objects`): политики по `bucket_id` и разделу.
7. Значения по умолчанию, которые дают права при ошибке (например, роль `admin`, если профиль не загрузился).

Если доступен Supabase MCP — подтвердить находки по живой базе (`list_tables`, `execute_sql` только для чтения `pg_policies`, `get_advisors` type `security`).
