# Выпуск изменений

Что выпускаем: $ARGUMENTS

Код в `turo-fleet-archive/`, сайт https://turo-fleet-archive.vercel.app обновляется сам после push в `main`.

## Шаги

1. `git status` и `git diff` — убедиться, что в изменениях только нужное (нет `.env*`, `.next/`, временных файлов).
2. В `turo-fleet-archive/`: `npm test`, затем `npm run lint` и `npm run build`. Если что-то упало — исправить и повторить; не выпускать с ошибками.
3. Если изменилось поведение раздела — дописать коротко в `turo-fleet-archive/CLAUDE.md` (с датой).
4. Коммит: короткое сообщение на английском в стиле истории (`Раздел: что сделано`, например `Claims: Finish returns the car to work`).
5. **Спросить владельца перед push** — push в `main` сразу публикует сайт. Если работа в другой ветке — предложить слить её в `main` (или открыть PR).
6. После push: проверить GitHub Actions (`gh run list --limit 1`, при ошибке — `gh run view --log-failed`) и деплой Vercel (Vercel MCP, если подключён; иначе страница прод-сайта открылась с новыми изменениями).
7. Открыть изменённую страницу на сайте во встроенном браузере: обычная ширина и телефон (375px) — ничего не уезжает вбок, всё читается.
8. Коротко отчитаться владельцу простыми словами: что теперь работает и где посмотреть.
